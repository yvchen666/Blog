# 多线程任务系统

## 任务一：多生产者-多消费者扩展

### 需求分析
1. 支持至少3个生产者线程并行工作
2. 支持动态创建消费者线程（1-5个）
3. 保证数据最终一致性，每个元素仅被消费一次
4. 实现负载均衡策略

### 实现提示
- 使用线程池管理消费者
- 引入任务分发策略（轮询/随机）
- 增加线程ID追踪机制
- 修改停止策略为批量通知

### 测试用例
| 用例编号 | 测试场景                | 预期结果               | 验证指标           |
| -------- | ----------------------- | ---------------------- | ------------------ |
| TC-101   | 3生产者2消费者运行10秒  | 总生产数=总消费数      | 数据零丢失         |
| TC-102   | 动态添加消费者线程      | 新线程立即参与任务处理 | 负载均衡度变化≤15% |
| TC-103   | 突发高负载（1000req/s） | 系统吞吐量保持稳定     | 响应时间波动≤200ms |

## 任务二：队列容量限制与流量控制

### 需求分析
1. 实现队列最大容量限制（可配置）
2. 生产者阻塞式写入（队列满时等待）
3. 消费者主动拉取速率控制
4. 实时监控队列水位

### 实现提示
- 添加队列容量阈值参数
- 使用双条件变量（notFull/notEmpty）
- 实现动态扩容/缩容策略
- 集成Prometheus监控指标

### 测试用例
| 用例编号 | 测试场景                   | 预期结果               | 验证指标               |
| -------- | -------------------------- | ---------------------- | ---------------------- |
| TC-201   | 队列达到最大容量           | 生产者线程进入阻塞状态 | 线程状态显示WAITING    |
| TC-202   | 消费后唤醒阻塞生产者       | 生产者恢复工作         | 队列水位降至80%以下    |
| TC-203   | 持续超负荷运行（120%容量） | 系统拒绝服务并发出警报 | 错误日志包含"OVERFLOW" |

## 综合验证方案

### 端到端测试场景
1. **混合负载压力测试**
   - 并发执行：TC-101 + TC-201 + TC-301
   - 验证指标：系统吞吐量波动≤5%

2. **故障恢复演练**
   - 并发执行：TC-303 + TC-402 + TC-403
   - 验证指标：整体可用性≥99.99%

3. **长期稳定性测试**
   - 持续运行72小时
   - 监控指标：内存泄漏率/线程死锁/CPU毛刺

### 验收标准
1. 关键路径测试通过率100%
2. 非功能性指标达成率≥95%
3. 发现缺陷密度≤0.5个/千行代码
4. 系统恢复时间≤30秒

> 注：所有测试需在Linux/Windows双平台验证，硬件配置需记录基准参考值

## 知识总结

- 多生产者多消费者要先定队列的容量、阻塞条件和退出方式。
- 有界队列用来限流，满了必须有明确的拒绝或等待策略。
- 优先级队列要单独测优先级反转，不能只看平均延迟。
- 测试用例按场景编号即可，每个用例只验证一个失败模式。
