# GDB调试问题初步定位命令

进入gdb调试(pid为进程号)       PS：**需要注意一定要sudo**

```bash
sudo gdb attach pid
```

PS：附加调试后会有一段时间在加载，此时是无法操作的，需要等待直到可以输出 如图所示：

## 卡死问题

```bash
#进入gdb后的命令
bt
#bt是backtrace的缩写，用于显示当前线程的调用堆栈。
info threads
#这个命令用于显示当前进程中的所有线程的信息
```

PS：一页可能会显示不完全，可以按**ENTER**继续输出信息直到像图1出现(gdb)则输出完整

## 闪退问题

发生闪退时会自动停在闪退处，使用卡死问题相同命令查看即可

## 相关命令

查看进程号(xxxx为软件名称)

```bash
ps -aux |grep xxxx
```

```bash
#进入gdb后的命令
c
#c是continue的缩写，用于继续执行程序，直到下一个断点或程序结束
```

#### 核心转储文件：

**对于难以复现的“珍贵”现场**，可以使用核心转储命令，生成的文件目录位于进入gdb前的目录位置，文件**后缀为.core**

提供转储文件的同时**需要提供软件对应的hash值和版本号**例如：

```bash
generate-core-file
 #生成一个核心转储文件。
```

需要注意：核心转储文件一般非常庞大，生成非常耗时，在生成回传完成后，记得删除对应的文件，防止浪费存储资源。
