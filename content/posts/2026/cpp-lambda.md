# Lambda表达式

**Lambda 表达式的本质是编译器自动生成的一个匿名类（或结构体），并创建该类的一个临时对象**。这个类重载了函数调用运算符 `operator()`。

## 1.示例

```C++
int x = 10;
int y = 20;

auto lambda = [x, &y](int z) -> int {
    y = y + x + z; // 修改捕获的引用 y
    return x * z;
};

int result = lambda(5); // 使用 Lambda
```

编译器生成的

```C++
// 1. 编译器自动生成一个唯一的、匿名的类
class __SomeRandomlyGeneratedName__ {
private:
    int x;  // 按值捕获的变量，成为类的成员变量
    int& y; // 按引用捕获的变量，成为类的成员引用

public:
    // 2. 构造函数，用于初始化捕获的变量
    __SomeRandomlyGeneratedName__(int captured_x, int& captured_y)
        : x(captured_x), y(captured_y) {} // 初始化列表：x 是拷贝，y 是绑定引用

    // 3. 重载函数调用运算符 operator()
    int operator()(int z) const { // 注意：默认情况下是 const 的
        y = y + x + z; // 允许，因为修改引用指向的值不算修改成员本身
        return x * z;
    }
};

// 4. Lambda 定义处，相当于创建了这个匿名类的临时对象
int x = 10;
int y = 20;
auto lambda = __SomeRandomlyGeneratedName__(x, y); // 调用构造函数，初始化捕获列表

// 5. Lambda 调用处，相当于调用了该对象的 operator()
int result = lambda.operator()(5); // 等价于 lambda(5)
```

# 2. 核心原理分解

### a. 捕获列表的原理

捕获列表 **决定了匿名类有哪些成员变量**，以及这些变量是如何被初始化的。

- **按值捕获 `[x]`**： 相当于在匿名类中有一个 `int x;` 成员。在创建 Lambda 对象时，**当前作用域中的变量 `x` 的值会被拷贝**到这个成员中。此后，Lambda 内部使用的 `x` 是这个副本，与外界的 `x` 无关。
- **按引用捕获 `[&y]`**： 相当于在匿名类中有一个 `int& y;` 成员。在创建 Lambda 对象时，这个成员引用会**绑定到当前作用域中的变量 `y`** 上。此后，Lambda 内部对 `y` 的操作直接作用于外界原来的 `y`。

### b. `mutable` 关键字的作用

默认情况下，Lambda 的 `operator()` 被声明为 `const` 成员函数。这意味着你不能在 Lambda 内部修改按值捕获的变量（因为修改成员变量是非 `const` 操作）。

如果你使用了 `mutable` 关键字：

```C++
auto lambda = [x]() mutable { x++; };
```

编译器生成的 `operator()` 将**不再是 `const`** 的：

```C++
int operator()(int z) { // 去掉了 const
    x++; // 现在可以修改按值捕获的副本了
    return x * z;
}
```

注意：即使使用了 `mutable`，修改的也只是按值捕获的**副本**，不会影响外部原始变量。

### c. 实现原理的另一个视角：状态（State）

Lambda 表达式之所以强大，是因为它**既可以包含代码（可执行逻辑），也可以包含数据（捕获的状态）**。这个“状态”就是通过那个匿名类的成员变量来实现的。

这使得 Lambda 成为一个**闭包（Closure）**——一个带有状态的函数对象。你可以将它传递到其他函数（如 STL 算法）、存储起来，并在未来某个时刻调用它，而它依然能访问到当初创建它时捕获的那些数据（或数据的引用）。

## 3.值捕获、引用捕获

在使用 Lambda 处理如 `QEventLoop` 这类涉及生命周期和异步操作的对象时，使用什么捕获？

### 核心结论

对于 `QEventLoop loop;`应该使用**引用捕获 `[&]`**。

```C++
QEventLoop loop;
auto lambda = [&]() { // 使用引用捕获 &
    loop.exec();
};
```

### 详细分析和原理

#### 为什么是引用捕获？

1. **`QEventLoop` 不可复制**： `QEventLoop`（以及绝大多数 Qt 对象）继承自 `QObject`，而 `QObject` 没有拷贝构造函数和拷贝赋值运算符。这意味着你**无法按值捕获它**。如果你尝试写 `[loop]`，编译器会报错，提示你正在尝试使用一个被删除的（`deleted`）拷贝构造函数。
2. **我们需要操作的是“那个”loop对象**： 事件循环的核心是调用 `loop.exec()` 来**阻塞当前线程**，直到 `loop.quit()` 被调用。我们的目的就是让 Lambda 函数能够**操作**在外部创建的那个唯一的 `loop` 对象。如果我们按值捕获，即使可行，我们也只是操作了一个副本，而副本的 `exec()` 和 `quit()` 与原本的对象完全无关，根本无法控制我们真正想要阻塞的那个事件循环。
3. **生命周期是安全的**： 这是使用引用捕获最关键的前提。在这个场景中，`loop` 对象和 `lambda` 都是在同一个作用域（通常是某个函数或方法内部）中创建的。**`lambda` 的生命周期绝不会超过 `loop` 对象的生命周期**。也就是说，在 `loop` 对象被销毁（例如，函数返回）之前，`lambda` 肯定已经先被销毁或不再被使用了。因此，不存在“悬空引用”（Dangling Reference）的风险。

#### 为什么不能是值捕获？

正如第一点所述，语法上就不允许。即使语法允许，逻辑也是错误的，因为你操作的是一个副本。

#### 其他捕获方式

- **`[&loop]`**： 显式地按引用捕获 `loop` 对象。这是最清晰、最推荐的方式，明确了你的捕获意图。
- **`[=]`**： 默认按值捕获。不可行，原因同上。
- **`[this]`**： 如果这段代码是写在某个类的成员函数中，并且 `loop` 是该类的一个成员变量，那么你可以通过捕获 `this` 指针来间接访问 `loop`。但这引入了额外的风险（例如，如果 Lambda 被异步执行，而对象可能已被销毁），需要格外小心。

### 总结与最佳实践

1. **对于栈上对象且生命周期短于或等于 Lambda 的对象**（如本例中的 `QEventLoop`），使用**引用捕获 `[&]` 或 `[&loop]`**。
2. **绝对不要捕获不可复制对象的副本**。
3. **时刻警惕生命周期**：如果你需要将 Lambda 传递给一个异步上下文（例如，另一个线程、一个排队连接的槽、一个定时器），而 `loop` 对象可能先于 Lambda 调用而被销毁，那么就绝对不能使用引用捕获，否则会导致程序崩溃。在这种情况下，你需要重新设计代码结构（例如，使用 `QSharedPointer` 等进行生命周期管理）。
4. **清晰明了**：尽量使用显式捕获（如 `[&loop]`）而不是默认捕获（如 `[&]`），这样代码的读者能立刻知道 Lambda 依赖哪些外部变量。

## 4.GDB调试

### 1. `this` 指针是谁？

当断点停在由 `QtConcurrent::run` 启动的子线程的 Lambda 表达式内部时，**此处的 `this` 指针 `不是` 创建 Lambda 的那个对象的 `this`（如果是在类成员函数中创建的），而是编译器为 Lambda 生成的那个匿名类实例的 `this`**。

记住核心原理：**Lambda 是函数对象**。表达式 `[](){}` 会导致编译器生成一个匿名类。

```C++
// 编译器生成的类
class __AnonymousLambdaClass_123 {
    // 成员变量：用于存储捕获的变量
    // ...
public:
    void operator()() const {
        // 你的 Lambda 代码在这里
    }
};
```

当你写下：

```C++
QtConcurrent::run([](){
    // Lambda 函数体
    int x = 5; // 断点在这里
});
```

这大致等价于：

```C++
__AnonymousLambdaClass_123 lambda_instance;
QtConcurrent::run(lambda_instance);
```

因此，在 Lambda 函数体内部，`this` 指针指向的是 `lambda_instance` 这个对象。**它的类型是编译器生成的、唯一的匿名类型**。

**重要推论**：如果 Lambda 没有捕获任何变量（`[]`），那么这个匿名类就没有成员变量，`this` 指针也就没什么可看的。如果Lambda 按值捕获了变量（`[a, b]`），这些变量就会成为这个匿名类的成员，`this->a`, `this->b` 就是它们的值。如果按引用捕获（`[&a]`），那么 `this->a` 就是一个引用。

### 2. 寄存器情况是怎样的？

这取决于硬件架构和调用约定（calling convention）。在 x86-64 体系结构上，最常用的是 **System V AMD64 ABI** 调用约定。

- **`this` 指针**： 对于成员函数（包括 Lambda 的 `operator()`），`this` 指针通常通过 **`rdi`** 寄存器作为第一个隐含参数传递。
- **普通参数**： 如果Lambda 有参数，第一个参数在 `rsi`，第二个在 `rdx`，第三个在 `rcx`，第四个在 `r8`，第五个在 `r9`，更多的会通过栈传递。

所以，当断点停在 Lambda 内部时：

1. **`rdi` (或 `$rdi`)** 寄存器里存放的值就是 Lambda 函数对象的地址，也就是函数体内的 `this` 值。
2. 可以通过检查 `rdi` 指向的内存来查看捕获的变量。

### 3.`x` 命令简介

`x` 命令用于**检查内存**。它可以显示指定内存地址开始的内容，并以你指定的格式进行解释。这是调试时查看原始内存数据的强大工具。

### 基本语法

```cmd
x/[数量][格式][单位] <内存地址或表达式>
```

- **数量**：要显示多少个“单位”的数据。
- **格式**：如何解释和显示内存中的数据（例如，十六进制、十进制、字符等）。
- **单位**：每个数据单元的大小（例如，字节、字、巨型字等）。

#### 常用格式字母

| 字母 | 格式             | 说明           |
| :--- | :--------------- | :------------- |
| `x`  | 十六进制整数     |                |
| `d`  | 有符号十进制整数 |                |
| `u`  | 无符号十进制整数 |                |
| `t`  | 二进制           |                |
| `a`  | 地址             |                |
| `i`  | 机器指令         | 用于反汇编     |
| `c`  | 字符             |                |
| `f`  | 浮点数           |                |
| `s`  | C 字符串         | 遇到 `\0` 结束 |

#### 常用单位字母

| 字母 | 全称       | 大小（字节） |
| :--- | :--------- | :----------- |
| `b`  | byte       | 1            |
| `h`  | halfword   | 2            |
| `w`  | word       | 4            |
| `g`  | giant word | 8            |

### 示例

#### **第 1 步：找到 Lambda 对象的地址（`this` 指针）**

假设已经在 Lambda 函数体内部设置了断点

```cmd
(gdb) p /x $rdi
$1 = 0x7fffffffdb20 # 这是 Lambda 对象的地址
```

#### **第 2 步：使用 `x` 命令检查该地址的内存**

现在我们知道 Lambda 对象中有两个成员：

1. 一个 `int` (`x` 的副本，值 `10`)
2. 一个 `int*` 或 `int&` (`y` 的地址)

在 64 位系统上，内存布局很可能是这样的：

- `0x7fffffffdb20` - `0x7fffffffdb23`: 4 字节的 `int x` (值为 `10`)
- `0x7fffffffdb24` - `0x7fffffffdb2b`: 8 字节的 `int*` 或 `int&` (指向 `y` 的地址)

**但是考虑字节对齐的情况下，地址可能需要调整偏移量**

```cmd
(gdb) x/1wd 0x00007fffffffdbfc # 查看该地址的 1 个 “word”，用十进制
0x7fffffffdbfc: 10
(gdb) x/1gx 0x00007fffffffdbfc+8
0x7fffffffdc04: 0x00007ffe74a2beac #一个新地址，因为y是引用，指向y的地址
(gdb) x/1wd 0x00007ffe74a2beac
0x7ffe74a2beac: 20
```
